# HopZero Operational Troubleshooting Guide

This guide covers common diagnostic scenarios, operational edge cases, and self-healing procedures for the HopZero Email Forensics & BotChain Tool Suite.

---

## 1. Quick Self-Diagnostic
Before troubleshooting manually, run the built-in diagnostic utility:
```bash
python scripts/doctor.py
```
This utility audits Python versions, port bindings, disk capacity, database health, local Ollama models, and qualification registry checksums.

To export a sanitized support bundle (with all emails, IPs, and tokens automatically redacted):
```bash
python scripts/diagnostics.py --export
```

---

## 2. Common Scenarios & Solutions

### A. Port Conflict (Port 8000 or 5173 Already in Use)
- **Symptom**: `OSError: [Errno 98] Address already in use` or backend fails to bind.
- **Cause**: Another service or a previously running HopZero process is bound to port 8000 or 5173.
- **Resolution**:
  - The HopZero launcher automatically selects the next available port:
    ```bash
    python scripts/launch.py
    ```
  - Or manually specify custom ports:
    ```bash
    python scripts/launch.py --port 8080 --frontend-port 5174
    ```

### B. Ollama Daemon Unavailable or Resident Model Missing
- **Symptom**: `Ollama daemon not detected on 127.0.0.1:11434` or analysis falls back to rule-based explanations.
- **Resolution**:
  1. Start the Ollama background daemon:
     ```bash
     ollama serve
     ```
  2. Verify that the resident model is pulled:
     ```bash
     ollama pull hermes3:3b
     ```
  3. Verify resident model readiness:
     ```bash
     ollama list
     ```
  - *Note*: If Ollama is unavailable, HopZero automatically engages the deterministic offline fallback generator. Invariant 1 (zero LLM scoring authority) remains strictly protected regardless of Ollama status.

### C. Database Connection or SQLite File Locks
- **Symptom**: `OperationalError: database is locked` on desktop editions.
- **Resolution**:
  - HopZero automatically configures SQLite in Write-Ahead Logging (`WAL`) mode with a 5000ms busy timeout.
  - Ensure the user account has write permissions on the data directory:
    - Windows: `%LOCALAPPDATA%\HopZero\`
    - Linux: `~/.local/share/hopzero/`
    - macOS: `~/Library/Application Support/HopZero/`
  - If database corruption is suspected, restore the automatic pre-upgrade snapshot from `backups/`.

### D. Air-Gapped / Strictly Offline Operation
- **Symptom**: Outbound DNS resolution or external threat intelligence APIs fail.
- **Resolution**:
  - HopZero is architected for 100% offline air-gapped readiness.
  - Run the installer in offline mode:
    ```bash
    python scripts/install.py -y --offline
    ```
  - Verify complete network isolation:
    ```bash
    python scripts/test_network_isolation.py
    ```

## 3. Reporting Issues
If an issue persists, file a report using the [GitHub Issue Tracker](https://github.com/djbdvt-maker/Email_Analyser-/issues/new/choose) and attach the redacted archive generated by:
```bash
python scripts/diagnostics.py --export
```
